## 2. Alcance

**Objetivo del proyecto:** servidor MCP (Model Context Protocol) que expone herramientas de investigación y redacción jurídica sobre fuentes oficiales suizas — jurisprudencia federal y cantonal, legislación federal (Fedlex) y cantonal, publicaciones administrativas (SECO/BSV/ESTV), SHAB/FOSC/FUSC, análisis procesal y multirol, y redacción/revisión de escritos — sin fabricar ni aproximar contenido cuando una fuente oficial no está disponible.

**Componentes incluidos:**

- `apps/mcp-server` — servidor MCP (transporte stdio y HTTP).
- `apps/admin-cli` — CLI administrativa (no expone herramientas MCP).
- `packages/core`, `packages/shared`, `packages/shared-web`, `packages/documents`, `packages/citations` — núcleo, utilidades HTTP/seguridad compartidas, modelo normalizado, motor de citas.
- `packages/providers/*` — adaptadores de fuente: `entscheidsuche`, `fedlex`, `seco`, `bsv`, `estv`, `shab`, `cantonal` (LexWork/ZH/SZ/SIL/JU), `fixture`.
- `packages/updater` — actualizaciones firmadas, detección de brechas (capacidad administrativa, no MCP).

**42 herramientas MCP** registradas y verificadas (ver sección 4).

**Modo de release actual:** `PRIVATE_PERSONAL_BETA`.

**Publicación pública prevista:** sí (`PUBLIC_RELEASE_INTENDED: true`), pero no aprobada (`PUBLIC_RELEASE_APPROVED: false`) ni ejecutada (`PUBLICATION_PERFORMED: false`).

**Límites del RC:**

- No incluye revisión jurídica/procedimental humana cualificada (pendiente, ver sección 9).
- La calibración de confianza está completada solo para uso personal en beta privada (`PRIVATE_BETA_CALIBRATION_COMPLETED: true`), no para beta pública ni release público estable (ver sección 10).
- Cobertura cantonal de legislación: 24/26 cantones (TI y VD bloqueados legítimamente por barrera de acceso real de la fuente, sin alternativa oficial no agregadora — ver `docs/providers/cantonal-legislation.md`).
- SHAB/FOSC/FUSC: bloqueado permanentemente por política (`robots.txt: Disallow: /`), no por limitación técnica — ver secciones 4 y 6.
- No se ha creado repositorio Git ni se ha publicado el paquete.

## 6. Seguridad y cumplimiento

- **SSRF**: `DomainAllowlistResolver` valida cada salto de redirección (no solo la URL inicial) contra una allowlist por proveedor; resolución DNS explícita revalidada tras cada redirect (`packages/shared-web/src/secureHttpClient.ts`, cubierto por `secureHttpClient.test.ts`: bloqueo de dominio fuera de allowlist, bloqueo de DNS rebinding, validación DNS tras cada redirect).
- **Redirects**: límite máximo configurable (`DEFAULT_MAX_REDIRECTS = 5`), cada salto revalidado contra la allowlist y contra DNS antes de seguirlo.
- **HTTPS**: el cliente HTTP compartido solo opera sobre HTTPS por diseño (allowlist de dominio + esquema); sin degradación en este RC.
- **Protección contra decompression bombs**: `maxCompressionRatio` (por defecto 20x) y límites de bytes comprimidos/descomprimidos aplicados en `assertDecompressedLimit`, verificados con tests dedicados (expansión comprimida excesiva, `Content-Length` engañoso, respuesta chunked sin `Content-Length`) — sin cambios en esta fase salvo la corrección del defecto de doble descompresión (ver sección 8), que no relaja estos límites.
- **Secretos**: `pnpm pack --dry-run` sobre los 8 archivos reales del paquete (allowlist `files` de `package.json`; antes de la corrección de empaquetado eran 580, ver sección 8) no arrojó coincidencias de patrones de credenciales, claves privadas embebidas ni claves de acceso de servicios en la nube.
- **Breach detection**: `packages/updater/src/security.test.ts`, 3/3 tests PASS (parte de `pnpm run ci`).
- **robots.txt**: respetado sin excepción para SHAB — `ShabProvider` nunca realiza una petición HTTP real (`docs/providers/shab.md`); no hay scraping ni fallback de red bajo ninguna condición.
- **Comportamiento de política SHAB**: healthCheck permanece `healthy: false` con `unavailableByPolicy: { reason: "robots_txt_disallow" }` (nunca se falsea como sano); `tools/call` devuelve `PROVIDER_UNAVAILABLE_BY_POLICY` estructurado sin ejecutar el handler, por lo que `network_request_performed: false` es una garantía arquitectónica (el código que podría contactar `shab.ch` nunca se alcanza), no una afirmación no verificable.
- **Exención de fixture `transport@0.0.1`**: `THIRD_PARTY_NOTICES.md` — `transport@0.0.1 (requires_manual_review)`, el mismo fixture de test de la propia librería `pino` (logging) detectado en 2 rutas de resolución de `node_modules` (`node_modules/pino/test/fixtures/transport` y `node_modules/.pnpm/node_modules/pino/test/fixtures/transport` — hoisting de pnpm, no dos paquetes distintos). No es una dependencia de runtime real; confirmado ausente del tarball real (`pnpm pack --dry-run`, 0 ocurrencias de `node_modules` o de `transport@0.0.1` en la lista actual de 8 archivos — ver sección 3). La exención se documenta explícitamente, no se oculta del inventario (`docs/release/generated/license-inventory.json`: `manualReviewCount: 2`, `dependencyFixtureCount: 2`).

## 8. Cambios relevantes cerrados

- **Trazabilidad de fundamentos autónomos** (`officialSwissCaseResolver.ts`): corregida para no hardcodear un único caso, derivando `supporting_sections`/`ratio_evidence[].page_numbers` del texto, la posición y la adopción por el tribunal actual.
- **Páginas HTML**: `pagination_type: "html_unpaginated"` / `page_reference_status: "not_applicable_html"` — nunca se inventa un número de página para contenido no paginado (ver Ground 1/2 de 2A.348/2004, sección 5).
- **Páginas PDF**: `physical_page_count` se puebla y se usa como límite real para referencias de sección cuando el documento es un PDF paginado (verificado por test, ver limitación de evidencia en sección 5 para el caso concreto A-4733/2022).
- **Descompresión**: corregido un defecto de doble descompresión en `packages/shared-web/src/secureHttpClient.ts` — el `fetch` nativo de Node descomprime de forma transparente gzip/deflate/br en peticiones de red reales conservando el header `Content-Encoding`, y el cliente intentaba descomprimir de nuevo. La corrección solo acepta bytes ya descomprimidos cuando superan una verificación de firma (magic bytes `%PDF-` o validez UTF-8), preservando el rechazo de payloads realmente corruptos, los límites de tamaño/ratio y la protección contra decompression bombs. Restauró la disponibilidad real de `search_seco_documents`, `search_bsv_documents`, `search_estv_documents` y `get_cantonal_article` (36 → 40 de 42 herramientas activas).
- **SHAB**: nueva señal general `unavailableByPolicy`/`blockedByPolicy` (no específica del nombre "shab") que permite registrar y mantener visibles en `tools/list` las herramientas bloqueadas por política de cumplimiento permanente, distinto de un bloqueo transitorio de proveedor. `tools/call` devuelve `PROVIDER_UNAVAILABLE_BY_POLICY` estructurado sin petición de red (40 → 42 de 42).
- **Hostname/rutas locales**: eliminadas rutas absolutas de la máquina de desarrollo (patrón `/Users/<usuario>/...`) y su hostname real de los artefactos distribuidos (`claude-desktop-acceptance.json`, `mcp-persistence-check.json`, `multirole-persistence-check.json`, y dos páginas de documentación con ejemplos de configuración); el logger acepta un override opcional de hostname (`LOG_HOSTNAME`), inactivo por defecto en producción.
- **Conteo 42**: `expectedTools` del script de aceptación de Claude Desktop se deriva ahora de una única fuente de verdad compartida (`scripts/lib/tool-inventory.mjs`) en vez de una lista manual que había quedado desactualizada en 36.
- **Hash final**: la escritura del `.sha256` de `final-legal-capability-gate.json` se trasladó al mismo script que genera su contenido (`final-legal-capability-gate.mjs`), en vez de a un paso anterior del pipeline (`release-prepare.mjs`) que se ejecutaba antes de que ese contenido existiera — eliminando la condición de hash desfasado.
- **Package cleanup**: creado `.npmignore` (replicando `.gitignore` y añadiendo `.claude/settings.local.json`) para excluir del tarball la configuración local del harness sin perder las exclusiones existentes (`node_modules`, `dist`, `coverage`, etc.) ni borrar el archivo local.
- **`mandatoryTools` drift**: eliminada la lista manual redundante de 23 herramientas "obligatorias" en `claude-desktop-acceptance.mjs` — la coincidencia exacta ya exigida entre `expectedTools`/`toolsExposed` (0 missing, 0 unexpected, 0 duplicate) cubre esa condición sin una segunda lista que pudiera divergir.
- **Empaquetado no instalable (corregido)**: una validación de instalación limpia real (`pnpm pack` + instalación en un directorio temporal ajeno al workspace) descubrió que el tarball original solo contenía los `.ts` fuente del monorepo (580 archivos), sin `dist/` compilado, sin `bin`/`main`/`dependencies` en el `package.json` raíz, y con las dependencias de runtime reales de `apps/mcp-server` declaradas como `workspace:*` (irresolubles fuera del workspace pnpm) — el servidor no podía arrancar en absoluto tras una instalación real. Corregido con una arquitectura de bundle único vía `esbuild` (`scripts/build-package.mjs`): empaqueta `apps/mcp-server/src/stdio.ts` en `dist/stdio.js`, inlinea los 13 paquetes internos `@swiss-legal-mcp/*` y deja como dependencias externas reales solo los paquetes npm genuinos. `package.json` raíz ahora declara `main`/`bin`/`files`/`dependencies` reales; `files` actúa como allowlist estricta (8 archivos en el tarball final, ver secciones 3 y 6).
- **Frescura del bundle**: `scripts/lib/bundle-freshness.mjs` calcula un hash SHA-256 sobre el contenido de todas las fuentes `.ts` que alimentan el bundle (excluyendo `*.test.ts`) y lo registra en `dist/.source-hash.json` en cada `build:package`; `release-check.mjs` recalcula el hash actual y bloquea (`BLOCKED`) si no coincide con el registrado, evitando que un `dist/stdio.js` desactualizado pase inadvertido.
- **Gates bloqueantes en la cadena real de `ci`/`release:prepare`**: `build:package` corre como hook `prepack` antes de cualquier `pnpm pack` (incluido `--dry-run`), por lo que un fallo de compilación bloquea el empaquetado en cualquier punto donde se invoque. `release-prepare.mjs` ya no captura el fallo de `pnpm pack --dry-run` de forma silenciosa: vuelca `stdout`/`stderr` real del hijo, relanza el error (`exit code` distinto de 0) y borra cualquier `release-manifest.json` de una corrida anterior antes de intentar nada, para que nunca quede en disco un manifiesto que sugiera falsamente un release preparado con éxito. `test:legal-capability-live` y `test:package-install` se integraron en la cadena real de `ci`/`release:prepare` (antes solo se ejecutaban manualmente, fuera de esas cadenas).
- **Test dedicado de timeout real** (`packages/shared-web/src/secureHttpClient.test.ts`): 7 tests nuevos con un mock determinista de `fetch` que replica el `DOMException("AbortError")` real de Node — cubren abort real al superar `timeoutMs` sin esperar a que la respuesta tardía llegue, limpieza de `clearTimeout` tanto en éxito como en fallo (sin fugas de timer entre peticiones sucesivas), y los márgenes de carrera justo antes/después del límite. La protección SSRF de `DomainAllowlistResolver` (que rechaza explícitamente `localhost`/IPs privadas) hace arquitectónicamente imposible probar esto contra un servidor HTTP local real sin debilitar esa protección, de ahí el mock determinista en vez de un servidor real.
- **Regresión de los tres gates de empaquetado** (`tests/packagingReleaseGates.test.ts`, 9 tests): fallo real de `pnpm pack --dry-run` (vía un `pnpm` simulado en `PATH`) bloquea sin generar manifiesto; fallo real de `build:package` (fuente del bundle renombrada) bloquea; fallo real de `test:package-install` (misma causa) bloquea; verificación estructural (DFS con coloreado) de que el grafo de scripts de `package.json` no tiene ciclos; verificación de que `package-installability-check.mjs` nunca invoca `ci`/`release:prepare`/`release:check` (evita el bucle `pack → prepack → test:package-install → pack`).
- **Contención de recursos con `shutdown.test.ts` (corregida)**: los tests anteriores, al lanzar varios procesos reales pesados (`pnpm pack`, `pnpm add` en un directorio temporal, builds de `esbuild`), hicieron que `apps/mcp-server/tests/shutdown.test.ts` superase intermitentemente su timeout de 45s bajo la ejecución en paralelo por archivo de `vitest` — un caso real de contención de recursos, no una regresión lógica (confirmado por dos ejecuciones limpias consecutivas de la suite completa tras el cambio). Corregido siguiendo el mismo patrón ya usado en el repositorio para tests pesados (`packages/providers/*/src/liveIntegration.test.ts`): `tests/packagingReleaseGates.test.ts` se salta por defecto bajo `pnpm test`/`NODE_ENV=test pnpm test` y solo corre con `RUN_PACKAGING_GATE_TESTS=true`, invocado como paso propio y bloqueante (`pnpm test:packaging-gates`) dentro de `ci`/`release:prepare`, nunca dentro de la suite rápida.
- **FIND-01 y FIND-02 (validación cruzada IA-legal, `docs/validation/results/mcp-improvement-plan.md`)**: cerrados y reverificados de forma puntual contra el bundle real empaquetado. FIND-01 (P0, `MCP_DEFECT`): `resolve_official_swiss_case` con `require_full_text=true` fallaba de forma idéntica en AILC-06 (2A.348/2004) y AILC-13 (4C.4/2004) con `'excede el límite máximo de tokens permitido'` (109.737 caracteres en ambos casos); ahora recupera el texto completo con éxito (30.561 y 20.752 caracteres respectivamente, sin error de límite, sin necesidad de paginación). FIND-02 (P1, `MCP_DEFECT`): `search_cantonal_legislation` con `canton=GE` fallaba con `PARSE_ERROR: Respuesta comprimida inválida` contra `silgeneve.ch/legis/program/books/RSG/content.htm`; ahora devuelve 20 documentos reales desde esa misma URL sin error de descompresión. Los tres casos se repitieron 3 veces consecutivas con resultados idénticos (deterministas, no un éxito intermitente). Evidencia completa, incluyendo el tarball y su SHA-256, en `docs/validation/results/targeted-fix-find-01-02.json`/`.md`. FIND-03 a FIND-07 (P2/P3) permanecen sin tocar, fuera de este cierre.
